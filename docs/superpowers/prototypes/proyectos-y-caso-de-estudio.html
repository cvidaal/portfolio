01 · El problema

Cumpleaños gestionados por WhatsApp y libreta

Los parques infantiles reciben las reservas de cumpleaños por teléfono y mensajes. Se solapan franjas, las señales se cobran a mano y nadie sabe qué hay libre sin mirar la libreta. [confirmar con Carlos]

04 · Decisiones técnicas

Cuatro cosas que no pueden fallar

Cero overbooking

Si dos familias piden la última plaza a la vez, solo entra una: cada franja se bloquea dentro de la transacción antes de contar plazas.

// internal/booking/repository.go
lockKey := item.Date + " " + item.StartTime
tx.ExecContext(ctx, `SELECT pg_advisory_xact_lock(hashtext($1)::bigint)`, lockKey)
// ...cuenta las reservas activas de la franja
if count >= maxParties { return Booking{}, errSlotFull }
Pagos sin duplicados

Idempotency key por reserva, webhooks con firma verificada e importe comprobado.

Estados a prueba de errores

Máquina de estados con bloqueo de fila. Un cambio inválido devuelve 409.

Plazas que se liberan solas

Sin pago en 1 hora, la reserva caduca. El Checkout de Stripe caduca a la vez.

Listo para desplegar

Docker multi-stage, binario estático, usuario no root y healthcheck con BD.
